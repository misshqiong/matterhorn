# Matterhorn

Deterministic, evidence-backed temporal memory for agents. Writes are validated
against a closed schema; answers are derived from persisted assertions and
never generated by an LLM.

```console
pip install 'matterhorn[api,mcp,postgres]'
```

Claude Code project `.mcp.json`:

```json
{"mcpServers":{"matterhorn":{"command":"mh","args":["mcp","--db",".matterhorn/memory.db","--schema","org-matters/v1"]}}}
```

Ten-line embedded quickstart:

```python
from matterhorn import Engine
engine = Engine("memory.db", "org-matters/v1")
card = {"card_id": "1", "scope_id": "team", "subject_key": "release",
        "date": "2026-07-29", "title": "Release", "status": "open",
        "source_refs": [{"source_id": "m1", "sent_at": "2026-07-29T09:00:00Z",
                         "sender": "ada"}]}
engine.ingest([card])
answer = engine.query.current("team", "release", "status")
print(answer[0].value, answer[0].source_ids)
```

Corrections are a first-screen protocol, not cleanup work:

```python
engine.correct({"scope_id": "team", "subject_key": "release",
  "subject_type": "MATTER", "predicate": "status", "object_value": "closed",
  "valid_from": "2026-07-29T09:00:00Z",
  "source_refs": [{"source_id": "human-1", "sent_at": "2026-07-29T10:00:00Z",
                   "sender": "ada", "excerpt": "The release is closed."}]})
```

Operators can file the same correction from a YAML/JSON file with
`mh correct correction.yaml --db memory.db`, or use direct flags:

```console
mh correct --scope-id team --subject-key release --subject-type MATTER \
  --predicate status --object-value closed \
  --valid-from 2026-07-29T09:00:00Z \
  --source-ref '{"source_id":"human-1","sent_at":"2026-07-29T10:00:00Z","sender":"ada"}' \
  --db memory.db
```

The next query returns `closed` from the human assertion while retaining the
older assertion. Run the complete transcript in
[examples/correction](examples/correction/README.md).

## Why Matterhorn

- P1/P4: models are confined to write-side extraction; every read is
  deterministic.
- P5: cards, assertions, intervals, and answers retain evidence.
- P6: business effective time and system recorded time remain separate.
- P7/P9: assertions are append-only; projections are rebuildable and replay is
  idempotent.
- P8: human corrections are ordinary higher-priority assertions.

The normative contract is [spec/SPEC.md](spec/SPEC.md). Its 37 language-neutral
golden cases are a shared anti-drift asset:

```console
$ mh conformance run
SUMMARY passed=37 failed=0 total=37
```

## Use it

SQLite embed mode:

```python
engine = Engine("team.db", "org-matters/v1")
```

PostgreSQL service mode:

```python
engine = Engine(
    "postgresql://matterhorn:secret@primary:5432/matterhorn",
    "org-matters/v1",
)
```

The PostgreSQL DSN must target one writable primary. Replica routing and
read/write splitting violate read-after-write consistency and are rejected
when detectable.

REST:

```console
mh serve --db postgresql://matterhorn:secret@primary:5432/matterhorn \
  --host 0.0.0.0 --port 8000
```

Message streams can use the gated `MessageCardExtractor`. ReMe and OpenViking
digests can use deterministic adapters; both require real source metadata and
fail instead of fabricating evidence.
